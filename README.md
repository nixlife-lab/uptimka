**Лёгкий мониторинг VPS и домашних серверов на чистом Bash.**  
Красивый дашборд в терминале, контроль Docker-контейнеров и умные алерты в Telegram — без агентов, баз данных и веб-панелей.

## ⚡️ Почему uptimka?

Большинство систем мониторинга избыточны для одного VPS или хоумлаба: съедают сотни мегабайт RAM и требуют долгой настройки. **uptimka** — один Bash-скрипт:

- 🪶 **0 МБ в памяти:** запускается по таймеру, отрабатывает за пару секунд и выгружается.
- 🚫 **Без зависимостей:** только интерфейсы ядра (`/proc`, `/sys`) и стандартные утилиты (`awk`, `curl`, `df`, `ps`).
- 🎯 **Точные метрики:** CPU с учётом iowait и steal (важно на VPS), RAM по `MemAvailable`, температура именно процессора, несколько дисков.
- 🐳 **Docker под присмотром:** упавшие контейнеры, убитые по OOM, `unhealthy` по healthcheck и перезапускающиеся по кругу. Контейнеры, остановленные вручную (`docker stop`), не вызывают тревогу.
- 🛡 **Без спама:** повторный алерт по затянувшейся проблеме — раз в час (настраивается), но если ситуация изменилась — сообщение придёт сразу.
- ✅ **Отчёт о восстановлении** с длительностью проблемы и **уведомление о перезагрузке** сервера.
- 📊 **Регулярная сводка** в Telegram — раз в час, раз в день или раз в неделю: текущие показатели, пики за период и сколько было проблем.
- 📬 **Алерты не теряются:** если Telegram временно недоступен, сообщение отправится при следующей проверке.

**🔔 Проблема сохраняется** — напоминание раз в `ALERT_COOLDOWN` секунд.

**✅ Всё снова в норме** — когда показатели вернулись:

> ✅ **Сейчас всё в норме**  
>  
> **Сейчас:**  
> ⚡ CPU `7%` · нагрузка 0.21 / 0.18 / 0.15 (ядер: 4)  
> 🧠 RAM `41%` — 820 из 2000 МБ  
> 💾 Диск / `56%` — свободно 13G из 30G

> 🐳 Docker: работает 9 из 9, проблем нет

## 🚀 Установка

```bash
curl -sSL https://raw.githubusercontent.com/nixlife-lab/uptimka/main/install.sh | sudo bash
```

Установщик:
1. спросит `Bot Token` (ввод скрыт) и `Chat ID` и проверит их формат;
2. предложит пороги, список дисков, интервал проверки и как часто присылать отчёт;
3. отправит тестовое сообщение — и подскажет, что не так, если оно не дошло;
4. поставит проверку по расписанию: **systemd-таймер**, а если systemd нет — **cron**.

Ставится закреплённая версия (`v1.2.0`). Самую свежую из ветки `main` можно поставить так:

```bash
curl -sSL https://raw.githubusercontent.com/nixlife-lab/uptimka/main/install.sh | sudo UPTIMKA_REF=main bash
```

> 🔁 **Обновление со старой версии (nix-monitor).** Просто запустите установщик: он найдёт `nix-monitor`, перенесёт настройки и удалит старую версию.

<details>
<summary>Где взять Bot Token и Chat ID</summary>

1. Напишите [@BotFather](https://t.me/BotFather) → `/newbot` → получите токен вида `123456789:AAH...`.
2. Напишите своему боту `/start`.
3. Узнайте свой Chat ID, например через [@userinfobot](https://t.me/userinfobot). Для группы добавьте бота в неё — ID группы начинается с `-100`.

</details>

## 📖 Команды

| Команда | Что делает |
| :--- | :--- |
| `uptimka` | Показать дашборд |
| `uptimka -w` | Живой дашборд, обновление каждые 2 секунды (выход — `Ctrl+C`) |
| `sudo uptimka --test` | Отправить тестовое сообщение в Telegram |
| `sudo uptimka --report` | Отправить отчёт о сервере прямо сейчас |
| `sudo uptimka --cron` | Фоновая проверка и алерты (это запускает таймер) |
| `sudo uptimka --uninstall` | Удалить uptimka |
| `uptimka --version` | Версия |
| `uptimka --help` | Справка |

## ⚙️ Настройки — `/etc/uptimka/uptimka.conf`

```bash
# Telegram
BOT_TOKEN="123456789:AAH..."
CHAT_ID="987654321"

# Пороги алертов, %
CPU_THRESHOLD=85
RAM_THRESHOLD=90
DISK_THRESHOLD=90

# Точки монтирования для проверки, через пробел
DISKS="/ /mnt/data"

# Повторный алерт при затянувшейся проблеме — не чаще, чем раз в N секунд
ALERT_COOLDOWN=3600

# Сообщать, когда всё вернулось в норму / о перезагрузке
SEND_RESOLVE_ALERT=true
NOTIFY_REBOOT=true

# Docker-контейнеры, которые не нужно проверять (имена через пробел)
DOCKER_IGNORE="test-db old-app"

# Регулярный отчёт: off / hourly / daily / weekly
REPORT="daily"
REPORT_TIME="09:00"   # по часам сервера — проверьте командой date
REPORT_DAY=1          # для weekly: 1 — пн … 7 — вс
```

Перезапускать ничего не нужно — настройки читаются при каждой проверке. Если в пороге опечатка, uptimka возьмёт значение по умолчанию и покажет предупреждение в дашборде.

Интервал проверки меняется повторным запуском установщика (настройки при этом можно оставить).

## 📝 Что нового

**1.2.0**
- 📊 Регулярный отчёт о состоянии сервера: раз в час, день или неделю (`REPORT`, `REPORT_TIME`, `REPORT_DAY`) — с пиками CPU/RAM и числом проблем за период.
- 📬 Команда `--report` — отправить отчёт сейчас; в дашборде видно расписание отчётов.
- ⚙️ Установщик спрашивает, как часто присылать отчёт, и дописывает настройки в старый конфиг.

**1.1.0**
- 🐛 Живой режим `-w` теперь обновляет все показатели (раньше менялся только топ процессов) и не мерцает.
- 🎨 Новый дашборд с эмодзи и статусом «Всё в норме / Проблем: N»; рамка больше не съезжает.
- 🎯 CPU учитывает iowait, steal, irq и nice; RAM и аптайм читаются из `/proc` и не ломаются на русской локали; температура берётся с датчика процессора.
- 💾 Проверка нескольких дисков (`DISKS`), показ swap.
- 🐳 Docker: OOM, `unhealthy`, перезапуск по кругу; ручная остановка не считается сбоем; список исключений `DOCKER_IGNORE`.
- 📬 Алерт не теряется при сбое Telegram; спецсимволы в именах не ломают сообщение; новый алерт при смене ситуации; уведомление о перезагрузке.
- ⚙️ Установщик: проверка ввода, скрытый токен, systemd-таймер, закреплённая версия, переход с nix-monitor, удаление.
- ✨ Команды `--test`, `--help`, `--version`, `--uninstall`; защита от одновременных запусков; состояние в `/var/lib/uptimka` переживает перезагрузку.
